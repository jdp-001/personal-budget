Tożsamość projektu
******************
Projekt: PersonalBudget (C++)
Cel długoterminowy: Nauka programowania obiektowego poprzez budowę kompletnej aplikacji budżetowej.

Styl pracy
**********
1. Buduję frontalnie — zamykam moduły w całości.
2. Najpierw opis działania (jak tester), potem zmiana w kodzie.
3. Nie zostawiam pół-etapów funkcjonalnych.
4. OOP = odpowiedzialność za dane i zachowanie, nie mnożenie klas.
5. Menu jest centrum kontroli i testowania.
6. 1 commit = 1 zamknięty poziom funkcjonalny.

Procedura rozpoczęcia nowej sesji
*********************************
1. Uruchamiam program.
2. Przechodzę jeden pełny scenariusz użytkownika.
3. Opisuję słownie przepływ działania.
4. Definiuję jeden zamknięty cel sesji.
5. Dopiero potem zmieniam kod.

Procedura zamknięcia etapu
**************************
1. Test end-to-end (pełny scenariusz użytkownika).
2. Usunięcie kodu testowego / debug.
3. Commit (1 commit = 1 zamknięty poziom funkcjonalny).
4. Aktualizacja ARCHITECTURE.md, jeśli zmieniła się architektura.
